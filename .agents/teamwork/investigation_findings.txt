## 1. Executive Summary: Prior Attempt Audit & Critical Discoveries

The prior investigation correctly identified several structural bugs in the synchronization flow (such as the modal ID prefix check, missing startup sync, and refresh token overwrite). **However, a critical review reveals that the prior attempt contained fatal flaws in its proposed code fixes, missed several core root causes that break synchronization in practice, and failed to test HTTP CORS preflights and edge-case date handling.**

### Critical Defects & Corrections in the Prior Worker's Report:
1. **Fatal Flaw in Prior All-Day Event Fix (Google API Rejection)**:
   - *Prior worker proposed*: `start: { date: evt.start.slice(0, 10) }, end: { date: evt.end.slice(0, 10) }`.
   - *What the code/API actually requires*: In Google Calendar API v3, **all-day end dates are strictly exclusive** (`end.date > start.date`). For a single-day all-day event (e.g. `2026-09-30`), if `end.date` equals `start.date`, **Google Calendar API rejects the request with HTTP 400 Bad Request** (`"Invalid end time: end date must be after start date"`).
   - *Correction*: Single-day all-day events MUST compute `end.date` as `start.date + 1 day` (e.g. `2026-10-01`).

2. **Critical Flaw in Prior Timezone Date Key Fix (Western Hemisphere Shift)**:
   - *Prior worker proposed*: `const evtDate = new Date(evt.start); const startKey = !isNaN(evtDate.getTime()) ? formatDateKey(evtDate) : ...`.
   - *What the code/API actually shows*: For all-day events (`"2026-09-30"`), JavaScript `new Date("2026-09-30")` parses ISO date-only strings as **UTC midnight**. In all western timezones (e.g. US Eastern UTC-4/UTC-5, Pacific UTC-7/UTC-8), `evtDate.getDate()` shifts backward to September 29th (`2026-09-29T19:00:00-05:00`). The prior worker's proposed fix would break all-day events in the western hemisphere!
   - *Correction*: Pure date strings (`/^\d{4}-\d{2}-\d{2}$/`) must preserve their exact date key without passing through UTC `new Date()`. Only datetime strings with timestamps/offsets (containing `'T'`) should be converted to local time via `new Date()`.

3. **Missed Root Cause: CORS `OPTIONS` Preflight Fails with 401 Unauthorized (Live Verified)**:
   - The prior worker failed to test HTTP `OPTIONS` requests.
   - We executed a live probe against production:
     ```powershell
     curl.exe -s -i -X OPTIONS "https://lumina-vista-sigma.vercel.app/api/calendar/sync"
     ```
     **Live Response**:
     ```http
     HTTP/1.1 401 Unauthorized
     {"connected":false,"error":"Not connected to Google Calendar. Please authenticate."}
     ```
   - In [`api/calendar.js`](file:///c:/Users/roysu/LuminaVista/api/calendar.js#L217-L225), `handleSync` immediately demands a valid access token without checking if `req.method === 'OPTIONS'`. Browser preflight requests send neither cookies nor authorization headers. When running in cross-origin preview frames (like `/teamwork-preview`), browsers block the request before the POST or DELETE is ever transmitted!
   - In addition, [`vercel.json`](file:///c:/Users/roysu/LuminaVista/vercel.json#L19-L24) sets `Access-Control-Allow-Methods: GET, POST, OPTIONS`, **omitting `DELETE`**.

4. **Missed Root Cause: False Positive "Connected" State in `handleStatus`**:
   - In [`api/calendar.js#L154-L155`](file:///c:/Users/roysu/LuminaVista/api/calendar.js#L154-L155), `handleStatus` tests `const connected = !!cookies.gcal_token;`.
   - It **never verifies** whether the access token or refresh token is valid! Even if the token is completely expired, invalid, or revoked, `handleStatus` returns `connected: true`. The frontend displays a green "Google Synced" badge while every background sync fails with 401.

5. **Missed Root Cause: Asynchronous Popup Blocker Drop without Fallback**:
   - In [`modules/calendar.js#L1264-L1276`](file:///c:/Users/roysu/LuminaVista/modules/calendar.js#L1264-L1276), `window.open` is called **after** an asynchronous `await fetch('/api/calendar/auth')`.
   - In Chrome, Safari, and Edge, user gesture tokens expire after network round-trips; popups are blocked by default.
   - If blocked, `popup` is `null`. The first tick of `setInterval` evaluates `if (!popup || popup.closed)` as true, clears the timer, and silently halts with zero feedback to the user. Direct window navigation fallback (`window.location.href = authData.authUrl`) was missing.

6. **Missed Root Cause: AI Studio Auto-Planned Days Never Push to Google**:
   - [`aiAutoPlanDay()`](file:///c:/Users/roysu/LuminaVista/modules/calendar.js#L979-L1066) creates autonomous schedule items, saves them to localStorage, and renders them. It never calls `pushEventToGoogle()`.

7. **Missed Root Cause: Zero Periodic Auto-Sync Timer**:
   - There is NO background sync timer (e.g. every 5 or 10 minutes) or window focus sync in [`modules/calendar.js`](file:///c:/Users/roysu/LuminaVista/modules/calendar.js). Once loaded, LuminaVista never checks for changes made in Google Calendar unless manually triggered.

## 3. Detailed Technical Analysis Across Subsystems

### A. OAuth Flow & Token Management ([`api/calendar.js`](file:///c:/Users/roysu/LuminaVista/api/calendar.js))

1. **OAuth State Security & Parameter Encoding**:
   - In `handleAuth()`, `redirect_uri` is safely encoded into base64 JSON `state` and round-tripped through Google to `handleCallback()`. RFC 6749 Section 4.1.3 requires the token exchange `redirect_uri` to match the authorization `redirect_uri` character-for-character. This prevents code exchange failures.
2. **Refresh Token Permanent Erasure Bug**:
   - In `handleCallback()` lines 103-107:
     ```javascript
     const tokenPayload = JSON.stringify({
       access_token: tokenData.access_token,
       refresh_token: tokenData.refresh_token,
       expires_at: Date.now() + ((tokenData.expires_in || 3600) * 1000)
     });
     ```
   - Google only returns `refresh_token` when explicit consent is prompted or on first authorization. If a user re-authenticates and Google returns `{ access_token, expires_in }` without `refresh_token`, `tokenData.refresh_token` is `undefined`.
   - `JSON.stringify` drops the key or sets it to undefined, **permanently erasing the existing refresh token** from the user's cookie. After 60 minutes, the access token expires and the app is permanently locked out.
3. **Expired Token Return Bug**:
   - In `getValidAccessToken()` lines 208-210:
     ```javascript
     return tokenData.access_token || null;
     ```
   - If token refresh fails, this returns the expired access token. Downstream requests call Google API with an expired token, producing 401 errors. It must return `null`.
4. **Cookie Partitioning & Cross-Site Attributes**:
   - In `handleCallback()` and `getValidAccessToken()`, the cookie is set with `sameSite: 'lax'`.
   - When embedded inside an iframe (such as `/teamwork-preview`), `SameSite=Lax` cookies are stripped by Chrome/Safari/Edge.
   - Node test confirmed: `cookie.serialize('gcal_token', val, { partitioned: true, secure: true, sameSite: 'none' })` outputs `Secure; Partitioned; SameSite=None`. This ensures cookies persist in modern partitioned iframe contexts.

### B. Event Data Model & Google Calendar API v3 Compatibility

| Event Attribute | Google Calendar API v3 Spec | Current Lumina Implementation | Defect & Required Fix |
|---|---|---|---|
| **All-Day Event End Date** | `end: { date: "YYYY-MM-DD" }` (Strictly exclusive: `end.date > start.date`) | `start: { dateTime: new Date(evt.start).toISOString() }` | **Fatal**: Pushing `{ dateTime }` converts all-day events into timed events. Slicing raw date with equal start/end causes Google 400 error. Must compute `end.date = start.date + 1 day`. |
| **Cancelled / Deleted Instances** | `status: "cancelled"` | Imported unconditionally in `syncGoogleCalendar()` | Cancelled recurring instances lack `item.start`. Lumina defaults them to `new Date().toISOString()`, injecting phantom events. Must filter `item.status !== 'cancelled'`. |
| **Timezone Normalization** | Timed events returned in UTC RFC 3339 (`"2026-09-29T23:30:00Z"`) | `evt.start.slice(0, 10)` in `getEventsForDate()` | Slicing raw UTC string places late evening / early morning events on the wrong calendar day. Must convert UTC datetime strings to local date keys while preserving pure `YYYY-MM-DD` strings. |
| **Google ID Prefix (`gcal_`)** | Google event IDs are alphanumeric base32hex strings | Lumina prefixes local cache IDs with `gcal_${item.id}` | Modal edit checks `startsWith('evt_')`, completely ignoring `gcal_` events. Clicking an imported Google event opens a blank "Create" modal. |
| **Modal Datetime Input Format** | `<input type="datetime-local">` requires local `YYYY-MM-DDTHH:mm` | `evt.start.slice(0, 16)` | Slicing raw UTC ISO strings shows UTC time instead of local time in the modal. Saving shifts the event time by the user's timezone offset. |

```javascript
function getEventLocalDateKey(dateOrIsoStr) {
  if (!dateOrIsoStr) return '';
  // Pure YYYY-MM-DD date strings must NOT pass through new Date() to avoid UTC midnight drift in western timezones
  if (/^\d{4}-\d{2}-\d{2}$/.test(dateOrIsoStr)) return dateOrIsoStr;
  const d = new Date(dateOrIsoStr);
  if (isNaN(d.getTime())) return String(dateOrIsoStr).slice(0, 10);
  return formatDateKey(d);
}

function formatDateTimeLocalInput(isoOrDateStr) {
  if (!isoOrDateStr) return '';
  if (isoOrDateStr.length === 16 && isoOrDateStr.includes('T') && !isoOrDateStr.endsWith('Z')) return isoOrDateStr;
  const d = new Date(isoOrDateStr);
  if (isNaN(d.getTime())) return isoOrDateStr.slice(0, 16);
  const y = d.getFullYear();
  const m = String(d.getMonth() + 1).padStart(2, '0');
  const day = String(d.getDate()).padStart(2, '0');
  const h = String(d.getHours()).padStart(2, '0');
  const min = String(d.getMinutes()).padStart(2, '0');
  return `${y}-${m}-${day}T${h}:${min}`;
}
```

#### 4. Correct All-Day Formatting & Exclusive End Date in `pushEventToGoogle()`
```javascript
async function pushEventToGoogle(evt) {
  if (!calendarSettings.googleCalendarConnected) return;
  const fetchFn = (typeof window !== 'undefined' && typeof window.fetch === 'function') ? window.fetch : fetch;
  if (!fetchFn) return;

  const isAllDay = !!evt.allDay || (typeof evt.start === 'string' && evt.start.length === 10);
  let startPayload, endPayload;

  if (isAllDay) {
    const startDateStr = evt.start.slice(0, 10);
    let endDateStr = evt.end ? evt.end.slice(0, 10) : startDateStr;
    // Google Calendar API requires end date for all-day events to be strictly greater than start date (exclusive end)
    if (endDateStr <= startDateStr) {
      const sDate = new Date(startDateStr + 'T00:00:00');
      sDate.setDate(sDate.getDate() + 1);
      endDateStr = formatDateKey(sDate);
    }
    startPayload = { date: startDateStr };
    endPayload = { date: endDateStr };
  } else {
    startPayload = { dateTime: new Date(evt.start).toISOString() };
    endPayload = { dateTime: new Date(evt.end).toISOString() };
  }

  try {
    const res = await fetchFn('/api/calendar/sync', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      credentials: 'include',
      body: JSON.stringify({
        googleEventId: evt.googleEventId,
        eventId: evt.id,
        summary: evt.title,
        description: evt.description || '',
        location: evt.location || '',
        start: startPayload,
        end: endPayload
      })
    });
    if (res.ok) {
      const data = await res.json();
      if (data.item && data.item.id) {
        evt.googleEventId = data.item.id;
        saveCalendarEvents();
      }
    }
  } catch (e) {
    console.warn('Failed to push event to Google Calendar:', e);
  }
}
```

```javascript
async function syncGoogleCalendar() {
  updateSyncStatusBadge(true);
  try {
    const res = await fetch('/api/calendar/sync', { credentials: 'include' });
    if (res.ok) {
      const data = await res.json();
      if (data.items && Array.isArray(data.items)) {
        // Filter out cancelled events
        const activeItems = data.items.filter(item => item.status !== 'cancelled');
        const activeGoogleEventIds = new Set(activeItems.map(item => item.id));

        // 1. Two-Way Delete: Remove local Google-linked events deleted from remote

          if (!e.googleEventId) return true;
          return activeGoogleEventIds.has(e.googleEventId);
        });

        // 2. Two-Way Update & Add from Google
        activeItems.forEach(item => {
          const startStr = (item.start && (item.start.dateTime || item.start.date)) || new Date().toISOString();
          const endStr = (item.end && (item.end.dateTime || item.end.date)) || new Date(Date.now() + 3600000).toISOString();
          const allDay = !item.start || !item.start.dateTime;
```
